Harness Portal — Hướng dẫn sử dụng

Setup lần đầu → tạo project → gán budget → connect provider → đo token; và cách đưa một dự án đang chạy local vào quản lý tập trung. Placeholders: admin https://portal.example.com, member https://member.example.com. Author: Dau Sy Manh (manhds@) · Apache-2.0.

Portal cho bạn gì: tạo Project → thêm Member → gán Budget (theo token hoặc chi phí ước tính) → connect AI provider (BYOK, key mã hoá) → đo token & chi phí + dashboard (bug/findings, prompt bị chặn, vi phạm, làm-lại). Điều kiện: Portal đã được deploy (xem runbook triển khai).

Phần 1 — Vận hành Portal

  1. First-time setup (Org Admin). Mở admin UI https://portal.example.com → tab First-time setup → nhập Setup key (giá trị SETUP_GATE_KEY người deploy đặt trên server; nhập sai 5 lần từ một IP thì IP đó bị khoá setup 8 giờ — mặc định) + Organization name + tên hiển thị + email + mật khẩu mạnh → Create organization. Các lần sau dùng tab Login (có “Remember me for 1 week”). Nút Đăng nhập bằng Google chỉ hiện khi server đã cấu hình OIDC.
  2. Tạo Project. Màn Projects (menu Quản lý) → nhập Project name, Description, chọn Đơn vị (hoặc “Gốc tổ chức”) → + New Project. Ví dụ acme-web. Mỗi project là ranh giới quản lý (member, budget, provider, log riêng).
  3. Gán Budget. Mở project → tab Budgets → chọn phạm vi (Whole project hoặc một member) → Period (monthly / daily / session) → Limit on: Tokens (mặc định) / Estimated cost ($) / Either (first hit) → Max tokens, Max est. cost ($), Alert at % (vd 80) → When exhausted: off (form ghi “ignore”: không cảnh báo, không chặn qua PDP) / warn (chỉ cảnh báo) / ask (PDP giữ hành động rủi ro chờ admin duyệt ở Approvals) / deny (PDP chặn) → Set budget. Lưu ý: proxy Tier-1 không đọc chế độ này — hết 100% là trả 402 ở mọi chế độ, kể cả off.
    • Chỉ cap của trục Limit on quyết định “cạn”; cap để 0 hiện là unset — trục đó không chặn gì.
    • Cost chỉ là ước tính (token × giá niêm yết API). Dùng subscription (Claude Code, Codex) thì không ai bị tính số tiền đó → nên giới hạn theo token, trừ khi project thật sự trả tiền theo token.
    • Kỳ daily/monthly đếm cả token từ telemetry (Claude Code/Codex) mỗi lần ingest; kỳ session chỉ đếm request qua proxy. Khi chạm ngưỡng % hoặc 100%, Portal tạo 1 incident (tab Security) + gửi email/webhook nếu đã cấu hình — một lần mỗi kỳ, trừ khi chế độ là off. Việc kiểm tra này chạy lúc ingest telemetry có agentops.log (push, hoặc server đọc checkout), không chạy ở mỗi request proxy: request proxy chỉ bật cờ budget_alert trong response (panel Try it hiện ra). Project chỉ dùng proxy mà không có telemetry thì không có incident, không có email.
    • ask/deny tác động qua PDP (cần pdp_enforce:true, Phần 2 bước 4) và chỉ giữ/chặn hành động rủi ro mà hook gửi lên PDP — không chặn token chat thường. Proxy Tier-1 thì trả 402 khi budget đã cạn, bất kể chế độ.
  4. Connect Provider (BYOK). Tab Providers → chọn provider (Anthropic API (Claude) / OpenAI / Deepseek / Qwen / GLM = Tier-1 đo token thật; Claude Code / GitHub Copilot / Codex CLI / Local (Ollama, on-prem) = Tier-2 best-effort) → đặt Display name → với Tier-1 dán API key (Tier-2 không cần key) → Connect provider. Key được mã hoá khi lưu (đọc DB chỉ thấy ciphertext, API luôn mask). Dự án dùng từ 2 tài khoản Claude trở lên: đặt tên mỗi connection trùng nhãn đã dùng trong harness-switch-account.ps1.
  5. Đo token. Với connection Tier-1: gửi request qua proxy của Portal — mỗi lần đo chính xác tokens_in/out + chi phí, cộng vào budget, cảnh báo ở ngưỡng, chặn 402 khi cạn. Dùng panel “Try it” (tab Overview của project trong member UI), hoặc gọi API: 
    POST https://portal.example.com/api/member/projects/{project_id}/proxy/chat
{ "provider_connection_id":"...", "model":"...", "messages":[{"role":"user","content":"hello"}] }
  6. Thêm Member. Tab Members của project → nhập email, chọn role (member / admin) → + Add member → Portal sinh invite link (nút Copy; gửi email nếu bật SMTP) → member mở https://member.example.com/accept-invite?token=... đặt mật khẩu. Member UI (My Workspace): menu Dự án của tôi chỉ liệt kê project được cấp; mỗi project có tab Overview (budget chung của project + budget cá nhân, provider với key mask, Try it), My Log, My Security Flags, My Prompt Scores. Ai được cấp quyền theo đơn vị thì có thêm báo cáo đơn vị trên thanh menu.
  7. Theo dõi. Per-project tabs: Dashboard (token/cost hôm nay·tháng·tổng, theo trợ lý AI, member, provider; budget), Harness Level (CASAN H1–H7 + H3 release gate), Settings, Members, Providers, Budgets, Bundle (gán phiên bản bundle), Action Log, Security, Prompt Score, Source/Doc, Test Report, Bug List (M6). Menu trái (17 màn):
    • Tổng quan — Harness Level, Fleet Health, CASAN Rubric, Criteria Overview, Conventions, Rule Compliance, Approvals (duyệt hành động rủi ro).
    • Bằng chứng — Audit Explorer (mọi tool call có side-effect), Security Feed, Cost & Budget (token/chi phí toàn tổ chức, hạn mức, dự phóng), Agent Runs.
    • Quản lý — Đơn vị (tối đa 2 cấp), Phân quyền (view/edit theo tổ chức / đơn vị / dự án), Projects, Members, Bundles, Common Bug (bug tái diễn/quan trọng toàn tổ chức).
    Approvals và nhóm Quản lý (trừ Common Bug) chỉ hiện với Org admin. Ô Phạm vi trên cùng lọc mọi báo cáo theo toàn tổ chức / đơn vị / dự án.

Phần 2 — Đưa một dự án đang chạy local vào quản lý

Kịch bản: bạn đã có một dự án chạy local (đã dùng nhiều), giờ muốn quản trị nó qua Portal như các service khác trên máy. Harness chạy ngay trong repo dự án (không đổi cách bạn chạy app); Portal đọc lại log/telemetry của repo đó để hiển thị tập trung.

  1. Cài governance bundle vào repo dự án (một lần): 
    # Windows (PowerShell 5.1)
powershell -File C:\path\to\HarnessAI-ToolKIT\tools\harness-bundle\install.ps1 -BundleFile C:\path\to\HarnessAI-ToolKIT\bundles\standard-governance\standard-governance-<latest>.bundle.json -TargetDir C:\path\to\my-service
# macOS/Linux
bash /path/to/HarnessAI-ToolKIT/tools/harness-bundle/install.sh --bundle /path/to/HarnessAI-ToolKIT/bundles/standard-governance/standard-governance-<latest>.bundle.json --target /path/to/my-service
    Bản mới nhất hiện là 1.8.0 (176 file). Thêm -DryRun / --dry-run để xem trước từng file (WRITE / KEEP / SKIP / MERGE / CONFLICT) mà không ghi gì. Kiểm đã áp đúng: powershell -File C:\path\to\HarnessAI-ToolKIT\tools\harness-bundle\harness-verify.ps1 -TargetDir C:\path\to\my-service → APPLIED OK. Khởi động lại Claude Code trong repo để hook có hiệu lực.
  2. Đăng ký dự án trên Portal (tab Settings của project): đặt
    • harness_root_ref = đường dẫn checkout thật của dự án (để Portal ingest log/telemetry của nó) — phải là đường bên trong container backend (đường Linux). Compose đi kèm (docker-compose.yml, docker-compose.prod.yml) không mount sẵn checkout nào vào backend, nên checkout trên server phải được bind-mount thêm bằng một file overlay của bạn (vd - /opt/my-service:/opt/my-service:ro dưới services.backend.volumes; mount cùng đường thì giá trị này trùng đường trên server). Checkout nằm trên máy dev thì dùng cách push ở bước 3.
    • gateway_base_url = URL gateway phục vụ checkout đó (nếu dùng đồng bộ qua gateway).
  3. Đồng bộ telemetry — 2 cách:
    • Server đọc trực tiếp (repo nằm cùng máy Portal và đã bind-mount vào container backend, như bước 2): Portal tự ingest mọi project có harness_root_ref đọc được, mỗi 5 phút (mặc định sẵn của backend, 300 giây; compose đi kèm không truyền biến AUTO_INGEST_INTERVAL_SECONDS vào container, muốn đổi phải thêm nó vào environment của service backend). Muốn ngay: ⟳ Sync now ở màn Projects, hoặc Run ingest (tab Action Log) / Scan (Source/Doc) / Run test suites (Test Report) → Portal đọc .harness/ của checkout tại harness_root_ref. Đường không đọc được thì Run ingest báo “… not found” và ⟳ Sync now không tính project đó vào “Synced X/Y projects”.
    • Push từ máy dev (repo ở máy khác — phổ biến nhất): điền .harness/portal-sync.json {portal_url, project_id, member_email, pdp_enforce} (installer tạo sẵn file mẫu) + dán ingest key vào .harness/portal-sync.key (Settings → Push telemetry → Reveal ingest key), rồi chạy push-telemetry.ps1 (hook SessionEnd tự đẩy mỗi khi phiên kết thúc; muốn đẩy định kỳ thì tự đặt một scheduled task gọi script này). member_email = account chạy AI → gán token đúng member + provider connection. Làm một lệnh (cài bundle mới nhất với -Force + ghi portal_url/project_id + key + test push; giữ nguyên member_email/pdp_enforce đã có nhưng không tự điền hai trường này — tự thêm tay; bắt buộc truyền -PortalUrl thật): 
      powershell -File C:\path\to\HarnessAI-ToolKIT\tools\harness-bundle\setup-portal-sync.ps1 -ProjectDir C:\path\to\my-service -ProjectId <project-id> -IngestKey <ingest-key> -PortalUrl https://portal.example.com
    Cả hai đường đưa lên: action log, security incidents (prompt bị chặn/vi phạm), token usage (agentops), prompt scores (review verdict), test reports (H3), và bug list (M6); source↔doc mapping (H1) đến qua push hoặc nút Scan. Đường push còn gửi bằng chứng CASAN/doctor cho Harness Level và Fleet Health.
  4. Bật chặn server-side (tuỳ chọn). Đặt pdp_enforce:true trong portal-sync.json → hook PreToolUse hỏi Portal PDP (chỉ với lệnh dạng rủi ro cao): chặn outbound ngoài allowlist (H4), giữ deploy/DB-write chờ admin duyệt ở màn Approvals (H5), chặn release nếu test/verdict fail (H3), và giữ/chặn hành động khi budget đã cạn ở chế độ ask/deny. Fail-open (defense-in-depth, C10).
  5. Gán budget + connect provider cho project (như Phần 1) nếu muốn đo/chặn chi phí.
  6. Lặp cho từng dự án local khác. Mỗi dự án = 1 project trong Portal; bạn quản lý tập trung nhiều dự án cùng lúc, mỗi cái vẫn chạy độc lập trên máy.
Trung thực về đo token (C10): Portal đo chính xác chỉ với request gửi qua proxy Tier-1 của Portal. Token mà Claude Code (hay Codex) tiêu khi bạn code trong dự án là Tier-2 best-effort — hook đọc usage từ transcript phiên rồi đẩy lên qua telemetry; Portal không tự đo từng request và không chặn được token chat (giới hạn kỹ thuật, không hứa suông). Tiền hiển thị cho các phiên này là ước tính theo giá API, không phải hoá đơn. Muốn con số chi phí chính xác cho một luồng AI → cho luồng đó gọi model qua proxy Tier-1.
