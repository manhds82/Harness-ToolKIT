Harness Portal — Runbook triển khai lên server

Cách deploy Portal (admin + member + backend + Postgres) lên một server Linux đang chạy nhiều hệ thống khác mà không làm hỏng chúng. Placeholders: root@YOUR_SERVER, portal.example.com, member.example.com. Author: Dau Sy Manh (manhds@) · Apache-2.0.

Nguyên tắc cô lập (áp dụng xuyên suốt): mọi thứ chạy trong một compose project riêng (network/volume/tên container riêng); container chỉ bind 127.0.0.1:<free-port>; không giành :80/:443; reverse-proxy chỉ thêm vhost mới, không sửa vhost cũ. Gỡ sạch = docker compose -p <project> down.

Điều kiện

  • Server Linux có Docker + docker compose v2.24.4+ (file override dưới đây dùng tag !reset (cần ≥ 2.24) và !override (theo tài liệu Docker cần ≥ 2.24.4); Compose cũ hơn không hiểu), một reverse proxy (vd nginx) đang giữ :80/:443, và bạn ssh vào được.
  • 2 subdomain (hoặc 1) đã trỏ DNS về server: portal.example.com (admin), member.example.com (member).
  • Máy dev có PowerShell + OpenSSH client (để chạy script đưa source lên).

Các bước

  1. Đưa source lên server (nhập PAT 1 lần). Repo private → dùng script; PAT đi thẳng máy bạn → git credential store của server, không qua bên thứ ba: 
    powershell -File E:\SourceCode\HarnessAI-ToolKIT\tools\deploy\fetch-source-to-server.ps1 -Server root@YOUR_SERVER -Username <gh-user>
# -> /opt/harness-portal (source), /opt/harness-portal/portal (compose)
# (đổi E:\SourceCode\HarnessAI-ToolKIT nếu bạn clone toolkit chỗ khác)
    Chạy lại script này sẽ git fetch + reset --hard origin/main trên server — file chưa track (deploy.vars, docker-compose.server.yml) không bị đụng.
  2. Sinh secrets trên server (không commit, không để lộ). Nếu tooling của bạn chặn lệnh chạm .env, đặt tên file khác và dùng --env-file: 
    cd /opt/harness-portal/portal
cat > deploy.vars <<EOF
POSTGRES_USER=harness_portal
POSTGRES_DB=harness_portal
POSTGRES_PASSWORD=$(openssl rand -hex 24)
PORTAL_MASTER_KEY=$(openssl rand -hex 32)
JWT_SECRET=$(openssl rand -hex 32)
SETUP_GATE_KEY=$(openssl rand -hex 16)
ENVIRONMENT=production
EMAIL_BACKEND=console
KEY_PROVIDER=local
MEMBER_WEB_BASE_URL=https://member.example.com
ADMIN_VITE_API_BASE_URL=
MEMBER_VITE_API_BASE_URL=
EOF
chmod 600 deploy.vars
    Sao lưu PORTAL_MASTER_KEY vào vault. Mất nó = không giải mã được mọi provider key đã lưu. POSTGRES_PASSWORD, PORTAL_MASTER_KEY, JWT_SECRET, SETUP_GATE_KEY là bắt buộc — thiếu một biến thì docker compose dừng với thông báo "… is required". SETUP_GATE_KEY là Setup key của tab "First-time setup" (tạo org + admin đầu tiên): giữ riêng, đổi sau khi đã tạo org. Dùng gateway (--profile gateway) thì thêm GATEWAY_API_KEY=$(openssl rand -hex 24) (≥ 16 ký tự). SSO Google: thêm các biến OIDC_* (compose đã chuyển sẵn vào backend). Server đã dựng theo bản runbook cũ (chưa có SETUP_GATE_KEY trong deploy.vars)? Lần up kế tiếp sẽ dừng — chạy trước từ máy Windows: powershell -File E:\SourceCode\HarnessAI-ToolKIT\portal\scripts\rotate-secrets-and-check.ps1 -SshTarget root@YOUR_SERVER -DryRun, rồi chạy lại không có -DryRun (sinh key mạnh, backup deploy.vars cũ, không deploy).
  3. Chọn port trống + file override cô lập. Kiểm port đang dùng (ss -tlnH), chọn 2 port trống (vd 9600/9610). Tạo docker-compose.server.yml — không publish db/backend, web bind localhost: 
    services:
  postgres: { ports: !reset [] }
  backend:  { ports: !reset [] }
  gateway:  { ports: !reset [] }
  admin-web:  { ports: !override ["127.0.0.1:9600:80"] }
  member-web: { ports: !override ["127.0.0.1:9610:80"] }
    Dùng !override để thay port (không phải !reset [list], cái đó xoá sạch). Render kiểm trước khi chạy: docker compose --env-file deploy.vars -p harness-portal -f docker-compose.yml -f docker-compose.server.yml config | grep -E 'published|host_ip' — phải thấy đúng 127.0.0.1:9600/9610, không có gì khác. --env-file deploy.vars chỉ dùng để nội suy file compose — container backend chỉ nhận các biến có trong khối environment: của docker-compose.yml. Biến khác mà backend có đọc (SMTP_*, ALERT_WEBHOOK_URL, KMS_KEY_ID, AWS_REGION, PORTAL_CONFIG_DIR…) phải khai thêm ở đây, vd dạng khối: backend: { ports: !reset [], environment: { ALERT_WEBHOOK_URL: "${ALERT_WEBHOOK_URL:-}" } }.
  4. Build & chạy (project name riêng để cô lập tuyệt đối): 
    docker compose --env-file deploy.vars -p harness-portal \
  -f docker-compose.yml -f docker-compose.server.yml up -d --build
    Backend tự chạy alembic upgrade head && uvicorn … + healthcheck /healthz; web/gateway chờ backend healthy. Migration lỗi thì backend không lên (và web cũng không) — xem docker compose … logs backend, đừng đoán.
  5. Thêm vhost reverse-proxy + TLS (chỉ thêm file mới, không sửa cũ). Tái dùng cert wildcard sẵn có nếu domain đã có (vd Cloudflare Origin cert phủ *.example.com), hoặc certbot: 
    # /etc/nginx/sites-enabled/portal.example.com.conf
server { listen 80; server_name portal.example.com; location / { return 301 https://$host$request_uri; } }
server {
  listen 443 ssl http2; server_name portal.example.com;
  ssl_certificate     /path/to/fullchain.pem;
  ssl_certificate_key /path/to/privkey.pem;
  location / { proxy_pass http://127.0.0.1:9600; proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme; }
}
# (làm tương tự file member.example.com.conf -> 127.0.0.1:9610)
nginx -t && nginx -s reload   # test TRƯỚC, reload graceful (không rớt site khác)
    Web đã build same-origin (nginx trong container tự proxy /api → backend), nên vhost host chỉ cần forward toàn bộ về cổng web — không cần cấu hình CORS.
  6. Verify + kiểm không đụng ai: 
    cd /opt/harness-portal/portal
# cùng một lệnh compose cho mọi thao tác — thiếu --env-file thì compose dừng vì POSTGRES_PASSWORD "is required"
C="docker compose --env-file deploy.vars -p harness-portal -f docker-compose.yml -f docker-compose.server.yml"
$C ps                                                     # 4 container up/healthy
$C exec -T backend alembic current                        # phải kết thúc bằng "(head)" = revision mới nhất trong backend/alembic/versions
curl -sk --resolve portal.example.com:443:127.0.0.1 https://portal.example.com/   # 200 (cert origin dùng -k)
curl -s https://portal.example.com/api/auth/oidc/status   # {"enabled":false} (true nếu đã bật SSO) — proxy /api OK
docker ps -q | wc -l                                      # tổng = (cũ) + 4, không mất cái nào
    Kiểm thêm vài site cũ vẫn trả 200.
  7. Mở Portal lần đầu: https://portal.example.com → tab First-time setup → nhập Setup key (giá trị SETUP_GATE_KEY trong deploy.vars) → tạo Organization + Org Admin. Sai 5 lần / IP → IP đó bị khoá 8 giờ.

Cập nhật bản mới (các lần deploy sau)

Operator chạy từ máy Windows (C11) — portal/deploy-portal.ps1 dùng đúng bố cục của runbook này (/opt/harness-portal, project harness-portal, deploy.vars + docker-compose.server.yml) và đi qua một kết nối SSH:

powershell -File E:\SourceCode\HarnessAI-ToolKIT\portal\deploy-portal.ps1 -SshTarget root@YOUR_SERVER -DryRun   # in toàn bộ, không gửi gì
powershell -File E:\SourceCode\HarnessAI-ToolKIT\portal\deploy-portal.ps1 -SshTarget root@YOUR_SERVER
  • Preflight ở máy local: working tree sạch, HEAD = origin/main, test backend xanh, các web app build được (npm run build) — đỏ thì dừng. Nhưng nếu thiếu node_modules thì script chỉ in [WARN] … not compiled here và bỏ qua bước build web đó — chạy npm ci trong portal\<app> trước để preflight thực sự kiểm. -SkipTests bỏ qua cả test lẫn build web (chỉ in WARN).
  • Rollback point trước khi build: image đang chạy được tag harness-portal-<service>:rollback-<timestamp>.
  • Build rồi mới up (build lỗi thì container đang chạy không bị đụng) → verify: trạng thái container, route -VerifyRoute phải trả 401/403 (404 = image cũ vẫn chạy), alembic current = -ExpectAlembicHead, in kết quả -ReadBackSql → verify hỏng thì tự retag image cũ và verify lại. Dòng MARK … cuối cho biết dừng ở bước nào.
  • Đổi 3 tham số theo từng bản phát hành: -VerifyRoute (route do chính bản này thêm), -ExpectAlembicHead, -ReadBackSql. Để nguyên giá trị của bản trước thì verify có thể "xanh" trên image cũ.
  • Migration chỉ thêm cột có default thì rollback image an toàn; migration không additive cần kế hoạch rollback riêng — script không tự quyết.

Sao lưu / khôi phục Postgres

Overlay Caddy (docker-compose.prod.yml) có service pg-backup, nhưng overlay đó giành :80/:443 nên không dùng trên server chung. Dùng portal/scripts/backup.sh (cron) — truyền đúng lệnh compose qua biến COMPOSE, nếu không script gọi docker compose trần và không thấy project harness-portal:

cd /opt/harness-portal/portal
COMPOSE="docker compose --env-file deploy.vars -p harness-portal -f docker-compose.yml -f docker-compose.server.yml" \
  BACKUP_DIR=/var/backups/harness-portal RETAIN=14 ./scripts/backup.sh     # -> portal-YYYY-MM-DD_HHMMSS.sql.gz, giữ 14 bản mới nhất
Khôi phục cần một DB RỖNG — restore.sh không tự xoá gì. backup.sh chạy pg_dump dạng plain, không --clean, nên dump không có lệnh DROP; restore.sh đổ thẳng dump vào DB hiện có qua psql mà không bật ON_ERROR_STOP (dù comment đầu file nói "drops and recreates"). Khi backend đã từng chạy, alembic đã tạo đủ bảng → mọi CREATE TABLE/COPY đụng độ, psql chạy tiếp và script vẫn in done: dữ liệu không bị huỷ mà cũng không được khôi phục. Làm theo thứ tự dưới. Chưa được chạy thử — suy từ đọc backup.sh/restore.sh (C12); đọc kỹ output, có dòng ERROR: là khôi phục chưa trọn.
cd /opt/harness-portal/portal
C="docker compose --env-file deploy.vars -p harness-portal -f docker-compose.yml -f docker-compose.server.yml"
# 0) backup bản hiện tại trước (lệnh backup.sh ở trên) — bước 2 XOÁ DB
# 1) dừng mọi thứ ghi DB; backend khi lên sẽ chạy alembic và tạo lại bảng
$C stop backend admin-web member-web            # + gateway nếu có chạy
# 2) DB rỗng: xoá rồi tạo lại (POSTGRES_USER của image postgres là superuser; đổi tên user/DB ở deploy.vars thì sửa theo)
$C exec -T postgres psql -U harness_portal -d postgres -c "DROP DATABASE harness_portal"
$C exec -T postgres psql -U harness_portal -d postgres -c "CREATE DATABASE harness_portal OWNER harness_portal"
# 3) nạp dump (hỏi gõ lại tên DB để xác nhận)
COMPOSE="$C" ./scripts/restore.sh /var/backups/harness-portal/portal-<STAMP>.sql.gz
# 4) chỉ bây giờ mới bật lại backend — alembic đọc revision có trong dump, nâng tiếp nếu cần
$C start backend admin-web member-web
$C exec -T backend alembic current              # phải kết thúc bằng "(head)"

Dump chỉ chứa ciphertext của provider key — khôi phục cần cùng PORTAL_MASTER_KEY đã dùng khi ghi dữ liệu. Hai script mặc định POSTGRES_USER/POSTGRES_DB = harness_portal (khớp deploy.vars ở bước 2); đổi tên thì truyền kèm hai biến đó.

Gỡ / rollback

cd /opt/harness-portal/portal
C="docker compose --env-file deploy.vars -p harness-portal -f docker-compose.yml -f docker-compose.server.yml"
$C down            # gỡ container (giữ volume dữ liệu)
$C down -v         # gỡ cả volume (XOÁ dữ liệu Portal)
rm /etc/nginx/sites-enabled/portal.example.com.conf /etc/nginx/sites-enabled/member.example.com.conf && nginx -t && nginx -s reload
Trung thực / an toàn (C10): cô lập theo compose-project nghĩa là build lỗi cũng không hỏng hệ khác; nhưng luôn render config để chắc port đúng trước khi up, và nginx -t trước khi reload. Không dùng overlay Caddy giành :80/:443 trên server đã có reverse proxy. Secrets sinh trên server, không commit.
